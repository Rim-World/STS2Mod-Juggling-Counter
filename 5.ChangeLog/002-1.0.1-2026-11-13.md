# 版本 1.0.1（2026-11-13）

- **版本号**：1.0.1
- **时间戳**：2026-11-13（+0800）
- **开发人员反馈**：用户提供 v0.113.0 参考库要求核对，并反馈角标与官方数字疑似相差 1px。核对发现 0.113 的四类补丁点、场景布局与 manifest 全部兼容；真正需要改的是"球"换手场景下的打出者归属。1px 经同字体渲染复现，确认是数字轮廓与缩放栅格化，不是布局偏移。
- **实装更改概括**：
  - 统计谓词由 `e.CardPlay.Card.Owner.Creature == power.Owner` 改为 `e.Actor == power.Owner`，修复卡牌打出后易主导致计数串账的问题。
  - manifest 版本 `1.0.0` → `1.0.1`，csproj 新增 `<Version>1.0.1</Version>`（AssemblyVersion 1.0.1.0）；补丁点、布局常量、pck 资源均未改动。
  - 以 v0.113.0 的 `sts2.dll` 重新编译，单一 DLL 继续兼容 v0.107 / v0.111 / v0.113。
- **简略技术细节**：
  - `CardPlayStartedEntry` 构造时把 `cardPlay.Card.Owner.Creature` 快照进基类 `CombatHistoryEntry.Actor`；该快照不随 `Card.Owner` 后续变化，语义等于 v0.111+ 官方的 `CardPlay.Player`。
  - 0.113 官方 `JugglingPower.AfterApplied` 用 `e.CardPlay.Player == base.Owner.Player`；本 mod 用 `Actor` 以兼容 0.107（无 `CardPlay.Player`）。
  - 0.113 的 `JugglingPower.AfterSideTurnEnd(PlayerChoiceContext, CombatSide, IEnumerable<Creature>)` 参数名 `participants` 未变，既有 Postfix 正常绑定；`NPower.RefreshAmount` 仍为 private；`MegaLabel.SetTextAutoSize` 未变；`power.tscn` 的 `AmountLabel` 仍为 `-56..44`、右对齐、字号 18、描边 10。
  - 角标 1px：Noto Sans Mono CJK SC 18px 下数字步进均为 9.0px，但右侧留白 0.666–1.134px；1.333 倍 canvas 缩放（1920×1080 基准 / 2560×1440 窗口）下，不同数字的最右墨迹列可相差 1px，同数字逐像素重合。官方层数标签同样如此，故不动布局。
  - 构建：`dotnet build`（net9.0 / Godot.NET.Sdk 4.5.1，引用 v0.113.0 `sts2.dll` + `0Harmony.dll`），0 警告 0 错误；ilspycmd 核对产物谓词无 `CardPlay.Player` / `Card.Owner` 引用。
- **失败经验或实验教训**：
  - "与官方 `AfterApplied` 同源"不等于"与官方计数永远一致"：官方在 0.111 就把回溯谓词换成了 `CardPlay.Player`，而 mod 为兼容 0.107 保留了 `Card.Owner` 链；0.111+ 引入的"球"会在打出后换手，重算历史时归属漂移。跨版本兼容不能只看成员是否存在，还要看语义是否随新内容改变。
  - 判断"1px 偏移"要先量矩形和字体：两个标签同为 `-56..44`、右对齐时，剩余差异只能来自字形轮廓；按数字墨迹强行补偿会偏离官方排版。
