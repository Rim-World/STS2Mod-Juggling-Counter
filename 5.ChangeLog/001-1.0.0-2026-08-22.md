# 版本 1.0.0（2026-08-22）

- **版本号**：1.0.0
- **时间戳**：2026-08-22（首次提交 18:45，1.0.0 版本提交 19:01，README 提交 19:14，均为 +0800）
- **开发人员反馈**：需求（"杂耍"buff 右上角显示本回合攻击牌数、始终显示含 0、不封顶）一次实现到位，构建 0 警告 0 错误；首个测试版暴露"计数滞后一张"问题，定位到补丁时机后修复一次通过；v0.107 兼容仅需改 1 行谓词 + 1 个 manifest 字段，双版本实测均正常。
- **实装更改概括**：
  - 新增 mod 本体：`JugglingCounterMod`（纯 Harmony 补丁，零第三方依赖），在铁甲战士能力牌"杂耍"（Juggling）的 buff 图标右上角显示"本回合已打出攻击牌数"，始终显示（含 0）、不封顶、回合切换归零。
  - 计数数据源为战斗历史（`CombatManager.History.CardPlaysStarted`）实时统计，与游戏内部计数同源。
  - 新增中英文发布文案（`description/`）、中英文 README、MIT LICENSE。
  - 支持 v0.107.x（default）与 v0.111.0（public beta）双版本，单一 DLL。
- **简略技术细节**：
  - 4 个 Harmony 补丁：`NPower.RefreshAmount` Postfix（创建/更新角标并注册）、`NPower._ExitTree` Postfix（注销）、`CombatHistory.CardPlayStarted` Postfix（攻击牌写入历史后刷新全部角标）、`JugglingPower.AfterSideTurnEnd` Postfix（己方回合结束置 0）。
  - 角标为 `Duplicate()` 自 `%AmountLabel` 的 `MegaLabel`，布局常量 `(-56, 0)`（图标右上角，与原层数标签同宽右对齐）；注册表按 Godot 节点实例 id 管理，`_ExitTree` 清理。
  - 统计谓词：`Card.Type == Attack && Card.Owner.Creature == power.Owner && HappenedThisTurn(power.CombatState)`（`Card.Owner.Creature` 链为 v0.107 官方写法，107/111 通用）。
  - 构建：`dotnet build`（net9.0 / Godot.NET.Sdk 4.5.1）→ Godot 4.5.1 `--import` + `--export-pack` 生成 pck（仅含 `JugglingCounterMod/mod_image.png`）→ 拷贝 dll/pdb/json/pck 到游戏 `mods/JugglingCounterMod/`；中间产物重定向到项目根 `%TEMP%`（仓库整理后归档至 `TMP/02-缓存与临时/`）。
  - manifest：`id=JugglingCounterMod`、`version=1.0.0`、`has_pck=true`、`has_dll=true`、`min_game_version=0.107.0`、`affects_gameplay=false`、`dependencies=[]`。
- **失败经验或实验教训**：
  - 刷新点不能选 `JugglingPower.BeforeCardPlayed`：该钩子为 Before 语义，执行时当前攻击牌尚未写入 History，导致角标恒滞后一张（打出第 2 张仍显示 1）。改为 `CombatHistory.CardPlayStarted` Postfix（History 已含当前牌）后正确。教训：UI 读取"记录型"数据时，必须挂在写入完成之后。
  - 模组图标需要 pck 提供 `res://{id}/mod_image.png`，原 `has_pck=false` 预案不成立（ADR-002 修正）。
  - MSBuild 命令行属性值中的 `%` 会被当作 item metadata 引用解析，传入 `%TEMP%` 路径须转义为 `%25`。
  - Godot 4.5.1 无 `--cache-dir`，`.godot` 缓存只能在工程目录生成后再移走。
