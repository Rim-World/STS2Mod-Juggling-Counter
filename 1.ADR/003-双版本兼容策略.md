# ADR-003：多版本兼容策略（v0.107 / v0.111 / v0.113 单一 DLL）

- 状态：已接受（2026-08-22，用户批准 v0.107 兼容修改；2026-11-13 修订统计谓词以适配 v0.113.0）
- 关联：[3.DOCS/004-R-v0.107兼容性核对报告.md](../3.DOCS/004-R-v0.107兼容性核对报告.md)、[3.DOCS/005-R-v0.113兼容性核对报告.md](../3.DOCS/005-R-v0.113兼容性核对报告.md)、[2.PLANS §12](../2.PLANS/001-G-杂耍计数实现方案.md)

## 背景

用户需在 default 分支 v0.107 上运行本 mod；游戏此前在 v0.111 上开发与验证。要求最低版本 0.107.0。

## 决策

1. **最低版本**：manifest `min_game_version = "0.107.0"`（0.107.1 与 0.111.0 均可加载）。
2. **统计谓词统一为 `e.Actor == power.Owner`**（2026-11-13 修订，原为 `e.CardPlay.Card.Owner.Creature`）：`Actor` 是 `CardPlayStartedEntry` 写入历史时对打出者的快照，107/111/113 均存在，且不会因卡牌之后易主而改变 → 单一 DLL 跨版本通用，不做条件编译、不做双包。
3. **以当前游戏分支的 sts2.dll 为编译目标**（1.0.0 为 107，1.0.1 为 113）：编译产物只引用各版本共有成员，在其它版本可解析（sts2.dll AssemblyVersion 固定 0.1.0.0，绑定无障碍）。
4. **刷新点保持 `CombatHistory.CardPlayStarted`**（与版本无关的 History 记录点）：v0.107 的 JugglingPower 在 `AfterCardPlayed` 计数、v0.111 用 `BeforeCardPlayed`、v0.113 在 `BeforeCardPlayed` 自增并在 `AfterCardPlayed` 复制——显示只读 History，不受机制差异影响。

## 影响与风险

- 修改面：1 行代码 + 1 个 manifest 字段；不触碰补丁目标、坐标常量、构建链。
- 风险：0Harmony 版本在 111 侧未直接实测（107 侧为 2.4.2.0）；切换版本时建议各实测一次（计划已含）。
- 约束：若未来游戏引入新机制且 mod 需要引用新成员，需重新评估"成员是否双版本共存"，必要时按版本分支。

## 验证结论（2026-08-22）

- ✅ default 0.107.x 实测通过；✅ public beta 0.111.0 实测通过（用户实测：两版本计数即时递增、复制触发、回合归零均正常）。
- 双版本单一 DLL 策略验证有效；后续版本更新按 plans §8 回归清单执行。

## 修订：v0.113.0 适配（2026-11-13，mod 1.0.1）

- **决策 2 的谓词改为 `e.Actor == power.Owner`**（不再使用 `e.CardPlay.Card.Owner.Creature`）。
- 原因：`CardPlayStartedEntry` 在写入历史时把 `cardPlay.Card.Owner.Creature` 快照进基类 `Actor`，之后卡牌易主不会改变它。v0.111+ 的“球”（The Ball）等牌打出后会被移交给另一名玩家，`Card.Owner` 随之改变；若每次刷新都用 `Card.Owner` 重算，这张攻击牌会被改记到另一名玩家头上，与官方计数（v0.111/113 用 `CardPlay.Player`）不一致。
- 跨版本性：`Actor` 在 0.107/0.111/0.113 均存在；`CardPlay.Player` 仅 111+ 有，仍不直接引用。0.107 没有“球”，显示结果不变。
- 复核结论：0.113 的 `JugglingPower` / `NPower` / `MegaLabel` / `power.tscn` / `ModManifest` 与 4 个补丁点全部兼容，详见 `3.DOCS/005-R`。
