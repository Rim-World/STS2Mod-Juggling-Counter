# ADR-002：构建与打包决策（v1.0.0）

- 状态：已接受（2026-08-22，用户批准开工并确认 author/版本/占位图标）
- 关联计划：[2.PLANS/001-G-杂耍计数实现方案.md](../2.PLANS/001-G-杂耍计数实现方案.md)

## 背景

用户批准直接开工并安装到游戏 `mods/` 目录；要求中间文件放项目 `%TEMP%` 目录并附说明；author 沿用"再玩小卡组找人弄你"；版本 1.0.0；模组图标用空白占位图。

## 决策

1. **manifest 参数**：`id=JugglingCounterMod`、`name=杂耍计数 (Juggling Counter)`、`author=再玩小卡组找人弄你`、`version=1.0.0`、`min_game_version=0.111.0`、`affects_gameplay=false`、`dependencies=[]`。
2. **has_pck: true（修正 ADR-001 的 has_pck=false 预案）**：游戏 mods 管理界面从 `res://{id}/mod_image.png` 加载模组图标（`NModInfoContainer.cs:87` 反编译确认），而 `res://` 需由 pck 提供 → 必须打 pck。pck 内仅含 `JugglingCounterMod/mod_image.png`（`export_filter="resources"` + 显式 `export_files` 清单，`%TEMP%` 等目录不会被包入）。
3. **模组图标**：420×420 正式图标（`pics/Juggling Counter_small.png`，用户提供，复制为 `9.SRC/JugglingCounterMod/JugglingCounterMod/mod_image.png`）。最初为 420×420 中灰纯色占位 PNG（由 `TOOLS/scripts/gen_mod_image.py` 生成，纯 Python 标准库手写 PNG，无第三方依赖；已由正式图标取代，脚本仅留档）。
4. **中间文件策略**：全部构建中间产物放项目根 `%TEMP%\` 目录下，与工程目录分离：
   - `%TEMP%\build\`：dotnet 编译输出（obj/bin 重定向）。Godot.NET.Sdk 默认把输出写到项目 `.godot/mono/temp`，且 `Sdk.targets` 无条件覆盖 `BaseOutputPath/OutputPath` → 通过命令行 global property 传入（`-p:BaseOutputPath/-p:OutputPath/-p:BaseIntermediateOutputPath/-p:IntermediateOutputPath`）。**注意**：MSBuild 属性值中的 `%` 会被当作 item metadata 引用解析，命令行值须把 `%` 转义为 `%25`（build.ps1 中实现）。
   - `%TEMP%\godot-cache\`：Godot `--import/--export-pack` 生成的 `.godot` 缓存目录（Godot 4.5.1 无 `--cache-dir`，只能在工程目录生成后移走；下次构建前若存在先移回复用）。
   - `%TEMP%\tools\`：一次性工具脚本（占位图生成）。
   - 说明文档：`%TEMP%\说明.md`。
5. **安装**：`build.ps1` 直接输出到 `C:\Game\Steam\steamapps\common\Slay the Spire 2\mods\JugglingCounterMod\`（dll + pdb + json + pck）。
6. **构建脚本**：沿用用户既有流水线（dotnet build → Godot import → export-pack → 拷贝），新增输出重定向与缓存归位逻辑。

## 被否/未采用方案

| 方案 | 理由 |
|---|---|
| has_pck=false（ADR-001 原预案） | 模组图标需 `res://{id}/mod_image.png`，无 pck 无法提供（RitsuLib 用 DLL 嵌入+运行时虚拟路径，复杂度高，不必要） |
| Godot `--cache-dir` 重定向 .godot | Godot 4.5.1 不支持该命令行选项（--help 实测） |
| 中间文件留在工程目录 | 违反用户"中间文件放 %TEMP%"要求 |

## 影响

- 工程目录保持干净（仅源码/配置/正式资源）；`%TEMP%\` 可整体删除而不影响工程与已安装 mod。
- **仓库整理（2026-11-01）后的实际位置**：原项目根 `%TEMP%` 目录内容已移入 `TMP/02-缓存与临时/`（`build/`、`godot-cache/`、`说明.md`），脚本移入 `TOOLS/scripts/`。`build.ps1` 未改动，仍按 `%TEMP%` 路径读写，因此下次构建会在项目根重新生成 `%TEMP%` 目录（属预期行为，不破坏构建）。
- 构建脚本是幂等的：重复构建会覆盖 mods 目录产物；`.godot` 缓存可复用（构建失败时可能残留工程内 `.godot`，下次构建前脚本会先清理/归位，见 build.ps1 逻辑——若残留则跳过恢复直接重建）。
