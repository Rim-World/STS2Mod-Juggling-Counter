# 002-S：v0.113.0 兼容修正与角标对齐核对

- 关联：[3.DOCS/005-R-v0.113兼容性核对报告.md](../3.DOCS/005-R-v0.113兼容性核对报告.md)、[1.ADR/003-双版本兼容策略.md](../1.ADR/003-双版本兼容策略.md)

## 1. 背景

用户提供 `STS2-Reference/3.STS2-113Reference`（v0.113.0 反编译源码 + 本地化 + filelist），要求核对 mod 是否需要改动；同时反馈"我们加的计数与官方数字似乎左右差 1px"。

## 2. 核对结论

| 事项 | 结论 |
|---|---|
| 0.113 补丁点（`NPower.RefreshAmount` / `_ExitTree` / `CombatHistory.CardPlayStarted` / `JugglingPower.AfterSideTurnEnd`） | 全部存在，签名/参数名不变 |
| `power.tscn` 层数标签布局 | `-56..44`、右对齐、字号 18、描边 10，与常量一致 |
| manifest / `ModManager` / `[ModInitializer]` | 无变化 |
| 统计谓词 | **需修正**：`Card.Owner.Creature` 在卡牌打出后易主时会串账（见下） |
| 角标 1px | **不是布局偏移**：两标签矩形与右缘完全一致；1px 来自等宽字体数字轮廓 + canvas 缩放（1.333x）与子像素相位的栅格化 |

## 3. 施工内容

1. `JugglingCounter.cs` 谓词由 `e.CardPlay.Card.Owner.Creature == power.Owner` 改为 `e.Actor == power.Owner`。
   - `CardPlayStartedEntry.Actor` 在写入历史时快照打出者，之后卡牌易主不改变；
   - 语义与 v0.111/113 官方 `JugglingPower.AfterApplied` 的 `e.CardPlay.Player` 一致；
   - `Actor` 在 107/111/113 均存在，不破坏单一 DLL 策略。
2. manifest 版本 `1.0.0` → `1.0.1`；csproj 增加 `<Version>1.0.1</Version>`。
3. 文档同步：ADR-003 修订、SDD、CHANGELOG、5.ChangeLog、README、3.DOCS 新报告、本计划。

## 4. 明确不做

- 不修改角标坐标常量 `(-56, 0)`：布局已逐像素对齐，按数字轮廓补偿会偏离官方标签排版。
- 不改补丁点、不改字体/描边/阴影、不改 pck 资源。

## 5. 验证

- `dotnet build`（v0.113.0 `sts2.dll`）：0 警告 0 错误。
- 产物反编译：谓词为 `((CombatHistoryEntry)e).Actor == power.Owner`，无 `CardPlay.Player` / `Card.Owner` 引用。
- 角标对齐：Godot 4.5.1 同字体同参数渲染，同数字逐像素重合；不同数字右缘 0–1px 摆动（官方标签同样）。
- 运行时：待用户安装 1.0.1 后在 0.113 实测（"球"换手场景需联机）。
- 对抗性审查（2026-11-13，只读）：三路独立子代理 + 主审复核谓词、刷新生命周期、113 假设；结论为 1.0.1 只需改谓词这一处，0 必须追加改动；非阻塞 P3 边界见 `3.DOCS/006-R`。
