## 11. Bug 修复记录（v1.0.1，2026-08-22）

**症状**（用户实测）：打出 1 张攻击牌再打出杂耍，角标显示 1；再打出第 2 张攻击牌角标保持 1 不变，直到第 3 张（触发复制）才变 2——计数恒滞后一张。

**根因**：刷新点选在 `JugglingPower.BeforeCardPlayed` Postfix。该钩子是 **Before 语义**：CardModel 打出流程（v0.111.0，CardModel.cs:1926-1929）中 `Hook.BeforeCardPlayed` 先于 `CombatManager.Instance.History.CardPlayStarted` 执行，Postfix 触发时**当前攻击牌尚未写入 History**，`CardPlayStarted.Count(...)` 统计少算当前这张 → 显示滞后一张；而"打出杂耍前"的牌已在 History 中，故初始显示正确。游戏内部计数不受影响（它在 `BeforeCardPlayed` 同步段自增），复制效果始终正确。

**修复**：刷新点改为 `CombatHistory.CardPlayStarted` Postfix（public 方法；全游戏唯一调用点 = CardModel.cs:1929，所有打出路径含自动打出/联机各端都经过）。该点执行时 History 已含当前牌，统计即"含本张"的正确值。删除 `Patches/JugglingBeforeCardPlayedPatch.cs`，新增 `Patches/CombatHistoryCardPlayStartedPatch.cs`；其余 3 个补丁不变（RefreshAmount 创建/更新、_ExitTree 清理、AfterSideTurnEnd 回合结束置 0）。

**验证**：场景 A（先 1 张攻击牌再杂耍）：显示 1 → 第 2 张后显示 2 → 第 3 张后显示 3 且复制触发 → 第 4 张显示 4。场景 B（先 2 张）：显示 2 → 第 3 张显示 3 且复制触发。

## 1. 需求（最终确认版）

1. 玩家拥有杂耍能力（`JugglingPower`）时，其 buff 图标右上角显示"本回合已打出的攻击牌数"。
2. 始终显示数字（含 0）；显示真实计数，不封顶（0、1、2、3、4…）。
3. 位置：图标右上角（与原右下角层数标签同宽同高、右对齐，y 移到顶部行）。
4. 纯显示增强：不改变任何游戏行为、不触碰卡牌/能力逻辑。
5. 零第三方依赖：纯 Harmony 自研（调研结论：BaseLib/RitsuLib 的角标 API 均因 `JugglingPower` 为 sealed 类而不可直接使用，仅借鉴其设计）。

## 2. 总体架构

```
游戏事件流                                 本 mod
──────────                                  ──────
NPower 创建/层数变化 → RefreshAmount()  ──▶  Patch① Postfix：创建/更新右上角角标 + 注册
NPower 移除           → _ExitTree()      ──▶  Patch② Postfix：注销（防泄漏）
玩家打出攻击牌        → JugglingPower.BeforeCardPlayed()
                                          ──▶  Patch③ Postfix：注册表全体刷新角标
玩家回合结束          → JugglingPower.AfterSideTurnEnd()
                                          ──▶  Patch④ Postfix：该实例角标显式置 0
```

- **数据源**：`CombatManager.Instance.History.CardPlaysStarted` 实时统计（与 `JugglingPower.AfterApplied` 完全相同的谓词），见 §3.1。公共 API，无反射。
- **UI**：`NPower` 上动态创建 `Duplicate()` 自 `%AmountLabel` 的 MegaLabel，见 §3.2。
- **注册表**：按 NPower 实例 id 跟踪的字典，`_ExitTree` 清理，见 §3.3。

## 3. 核心设计

### 3.1 计数统计（`JugglingCounter.CountAttacksPlayedThisTurn`）

```csharp
public static int CountAttacksPlayedThisTurn(JugglingPower power)
{
    var combat = CombatManager.Instance;
    if (combat?.History == null) return 0;
    return combat.History.CardPlaysStarted.Count(e =>
        e.CardPlay.Card.Type == CardType.Attack &&
        e.CardPlay.Player == power.Owner.Player &&
        e.HappenedThisTurn(power.CombatState));
}
```

- 与 `JugglingPower.AfterApplied` 的回溯谓词逐字一致 → 显示值永远等于游戏语义下的"本回合攻击牌数"。
- 回合边界自动归零（`HappenedThisTurn` 要求 round/side/全员 turn 一致），无需自维护清零状态机。
- 多 buff 实例/多玩家天然正确（各角标按自己的 `power.Owner` 统计）。
- 游戏内同模式先例：`LethalityPower`、`Normality`、`EchoFormPower`、`RingingPower` 等。

### 3.2 角标创建与更新（Patch①：`NPower.RefreshAmount` Postfix，private 方法）

```csharp
const string LabelName = "JugglingAttackCountLabel";

// 布局来源：power.tscn 实测 + RitsuLib ExtraCornerHostLayout 的 Power TopRight 常量

if (__instance._model is not JugglingPower power) return;

    var label = (MegaLabel)amountLabel.Duplicate();   // 继承字体/字号18/颜色/描边/阴影/右对齐
    label.Name = LabelName;
    label.UniqueNameInOwner = false;                  // 避免 unique 名冲突
```

- `RefreshAmount` 为 private → Harmony 用字符串名定位（先例：BaseLib `[HarmonyPatch("RefreshAmount")]`、RitsuLib `new(typeof(NPower), "RefreshAmount")`）。

### 3.4 刷新时机（Patch③ / Patch④）

- **Patch③** `CombatHistory.CardPlayStarted` Postfix（public 方法，`nameof` 可用）：
  ```csharp
  if (cardPlay?.Card?.Type != CardType.Attack) return;   // 仅攻击牌影响计数
  JugglingCounterRegistry.RefreshAll();
  ```
  **选择此点而非 `JugglingPower.BeforeCardPlayed` 的原因（v0.111.0 CardModel.cs 1926-1929 行实测）**：
  CardModel 打出流程中 `Hook.BeforeCardPlayed` 先于 `History.CardPlayStarted` 执行——Before 钩子的 Postfix 触发时**当前牌尚未写入 History**，会导致计数恒滞后一张（v1.0.0 实测 bug，见 §10 修复记录）。`CardPlayStarted` 是卡牌打出记录的唯一入口（CardModel.cs 唯一调用点），其 Postfix 执行时 History 已含当前牌。无需判断属主：每个角标按自己的 `Power.Owner` 统计，天然正确。
- **Patch④** `JugglingPower.AfterSideTurnEnd` Postfix：
  ```csharp
  if (!participants.Contains(__instance.Owner)) return;  // 与游戏内部清零条件一致
  JugglingCounterRegistry.SetZeroFor(__instance);
  ```
  必要性：玩家回合结束后到下一张攻击牌前没有 Patch③ 触发点；`AfterSideTurnEnd` 与游戏内部清零同点触发，显式置 0 与游戏语义精确同步（不依赖 History 的 side 切换时序）。敌人回合结束时 participants 不含我方 → 不处理。

## 7. 风险与应对

| 风险 | 应对 |
|---|---|
| 游戏更新导致 patch 目标签名/成员变化（`NPower.RefreshAmount`、`_ExitTree`、`JugglingPower.BeforeCardPlayed/AfterSideTurnEnd`） | 更新后跑"反编译比对 + 回归"（见 §8）；ModEntry try/catch，patch 失败仅丢角标不崩溃 |
| `power.tscn` 布局变化（`%AmountLabel` 坐标/字号） | 每次更新从 pck 重新提取 `scenes/combat/power.tscn` 复查坐标常量（提取脚本可复用） |
| 与其他 mod 同挂 `NPower.RefreshAmount` Postfix | 各补丁按自己的类型分支工作（BaseLib 查 `IHasSecondAmount`、RitsuLib 查接口、本 mod 查 `JugglingPower`），互不干扰 |
| `CombatManager.Instance` 在非战斗时刻被访问 | 统计函数空判断；角标只在战斗内 NPower 存在时创建 |
| 联机环境显示同步 | affects_gameplay=false；本地视角显示，无数据同步需求；如游戏强制 UI 同步再评估 |
