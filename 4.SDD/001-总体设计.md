# 001-总体设计：杂耍计数（JugglingCounterMod）

- 文档版本：v1（2026-11-01 整理，对应 mod 版本 1.0.0）
- 依据：`9.SRC/JugglingCounterMod/` 现有源码、`1.ADR/` 三篇决策、`2.PLANS/001-G-杂耍计数实现方案.md`、`3.DOCS/` 四篇调研与报告、manifest `JugglingCounterMod.json`
- 适用范围：本仓库当前实现（v1.0.0）。未在文档或源码中出现的设计内容一律标注"未记录"，不做推测。

## 1. 设计目标

| 目标 | 说明 | 依据 |
|---|---|---|
| 显示"本回合已打出攻击牌数" | 在铁甲战士能力牌"杂耍"（Juggling）的 buff 图标右上角显示计数，右下角原有层数（复制次数）不变 | ADR-001、`3.DOCS/001-E` |
| 纯显示增强 | `affects_gameplay=false`，不改卡牌效果、数值与游戏机制，不写存档 | manifest、ADR-001 |
| 始终显示真实数字 | 含 0，不封顶；回合切换归零 | ADR-001（用户确认的显示行为） |
| 零第三方依赖 | 不依赖 BaseLib / RitsuLib，纯 Harmony 自研 | ADR-001 |
| 单一 DLL 双版本 | 同时支持 v0.107.x（default）与 v0.111.0（public beta） | ADR-003、`3.DOCS/004-R` |
| 低回归面 | 补丁目标仅 4 处 + 1 组布局常量；补丁失败只丢角标，不崩溃 | ADR-001、`2.PLANS §7` |

## 3. 模块划分

```
JugglingCounterMod（单一 C# 程序集）
├── ModEntry            入口：Harmony.PatchAll + 全局 try/catch
├── JugglingCounter     统计：由战斗历史实时计数（纯函数）
├── JugglingCounterRegistry   UI 状态：角标创建/更新/注销 + 布局常量
└── Patches             4 个 Harmony 补丁（事件 → 上述两个模块）
    ├── NPowerRefreshAmountPatch          NPower.RefreshAmount        → Registry.Sync
    ├── NPowerExitTreePatch               NPower._ExitTree            → Registry.Unregister
    ├── CombatHistoryCardPlayStartedPatch CombatHistory.CardPlayStarted → Registry.RefreshAll
    └── JugglingAfterSideTurnEndPatch     JugglingPower.AfterSideTurnEnd → Registry.SetZeroFor
```

### 3.1 `ModEntry`（`ModEntry.cs`）

- `[ModInitializer("ModLoaded")]` 标记入口；`ModLoaded()` 内 `new Harmony("JugglingCounterMod")` 并 `PatchAll(Assembly.GetExecutingAssembly())`。
- 全部包在 `try/catch` 中：补丁应用失败只记录 `Log.Error`，不影响游戏启动。
- 常量 `ModId = "JugglingCounterMod"` 供日志前缀使用。

### 3.2 `JugglingCounter`（`JugglingCounter.cs`）

- 唯一公开方法 `CountAttacksPlayedThisTurn(JugglingPower power)`，返回本回合已打出攻击牌数。
- 数据源：`CombatManager.Instance.History.CardPlaysStarted` 实时筛选，谓词为
  `Card.Type == CardType.Attack && Card.Owner.Creature == power.Owner && HappenedThisTurn(power.CombatState)`。
- 与游戏内置 `JugglingPower.AfterApplied` 的回溯谓词同源，显示值恒等于游戏语义下的本回合攻击牌数；回合边界由 `HappenedThisTurn` 判定，无需自维护清零状态机。
- 谓词使用 `Card.Owner.Creature` 链（v0.107 的 `CardPlay` 无 `Player` 属性，该链在 107/111 均存在）。
- 空值保护：`power`、`power.Owner?.Player`、`combat?.History` 任一为空返回 0。

### 3.3 `JugglingCounterRegistry`（`JugglingCounterRegistry.cs`）

- 角标节点：动态 `Duplicate()` 自 `%AmountLabel`（`MegaLabel`），命名 `JugglingAttackCountLabel`，`UniqueNameInOwner=false`，插入到原标签同索引；继承原标签字体、字号、颜色、描边与右对齐。
- 布局常量：`CornerLeft = -56f`、`CornerTop = 0f`（与原层数标签同宽、右对齐，y 由原 `21..44` 移到 `0..23`，来自 `power.tscn` 实测 + RitsuLib `ExtraCornerHostLayout` 的 Power TopRight 常量）。
- 状态存储：`Dictionary<ulong, NPower>`，键为 Godot 节点实例 id；`lock` 保护遍历与写入（`RefreshAll` 在钓鱼/多线程事件中可能重入）。
- 方法职责：
  | 方法 | 触发者 | 行为 |
  |---|---|---|
  | `Sync(NPower)` | Patch①（`RefreshAmount` Postfix） | 非 `JugglingPower` 直接返回；确保角标存在 → 注册 → 更新文本 |
  | `RefreshAll()` | Patch③（`CardPlayStarted` Postfix） | 遍历注册表刷新所有角标；`IsInstanceValid` 为假的节点顺手清理；单个节点异常不中断其余节点 |
  | `SetZeroFor(JugglingPower)` | Patch④（`AfterSideTurnEnd` Postfix） | 匹配该 Power 的条目文本置 `"0"` |
  | `Unregister(NPower)` | Patch②（`_ExitTree` Postfix） | 移除实例 id 条目，防泄漏与悬挂回调 |
- 文本更新统一走 `UpdateText` → `MegaLabel.SetTextAutoSize(int.ToString())`，不改变字体尺寸行为。

### 3.4 补丁层（`Patches/`）

| 补丁 | 目标 | 类型 | 说明 |
|---|---|---|---|
| ① `NPowerRefreshAmountPatch` | `NPower.RefreshAmount` | Postfix | 方法为 private，用字符串名定位；先判 `IsNodeReady()`，再 `Sync` |
| ② `NPowerExitTreePatch` | `NPower._ExitTree` | Postfix | 注销注册表条目 |
| ③ `CombatHistoryCardPlayStartedPatch` | `CombatHistory.CardPlayStarted` | Postfix | 仅 `CardType.Attack` 触发 `RefreshAll`；该方法是卡牌打出记录的唯一入口 |
| ④ `JugglingAfterSideTurnEndPatch` | `JugglingPower.AfterSideTurnEnd` | Postfix | `participants` 含 `Owner` 时才 `SetZeroFor`（与游戏内部清零条件一致） |

每个补丁方法体均包 `try/catch` + `Log.Error`，异常不外抛。

## 4. 数据流

```
玩家打出攻击牌
  CardModel 打出流程
    → Hook.BeforeCardPlayed(...)                     （此时当前牌尚未写入 History）
    → CombatHistory.CardPlayStarted(combatState, play)（写入 History）
        → Patch③ Postfix → Registry.RefreshAll()
            → 每个角标：JugglingCounter.CountAttacksPlayedThisTurn(自己的 Power)
                → CombatManager.History.CardPlaysStarted 计数（含当前牌）

buff 图标创建 / 层数变化
  NPower._Ready → Reload → NPower.RefreshAmount()
    → Patch① Postfix → Registry.Sync(node)
        → 复制 %AmountLabel 建角标（幂等）→ 注册 → 按 History 计数写文本（含 0）

己方回合结束
  JugglingPower.AfterSideTurnEnd(participants)
    → Patch④ Postfix → Registry.SetZeroFor(power) → 角标文本 "0"

buff 图标移除
  NPower._ExitTree() → Patch② Postfix → Registry.Unregister(node)
```

关键时序约束：刷新点必须晚于 History 写入。v1.0.0 曾挂在 `JugglingPower.BeforeCardPlayed`（Before 语义，先于 History 写入）导致计数恒滞后一张，已改为 `CardPlayStarted`（记录见 `2.PLANS §11`）。

## 5. 数据结构

| 结构 | 定义 | 用途 |
|---|---|---|
| `Entries` | `Dictionary<ulong, NPower>`（`ulong` = `GodotObject.GetInstanceId()`） | 跟踪当前活跃的杂耍 buff 图标节点 |
| 角标节点 | `MegaLabel`，名称常量 `JugglingAttackCountLabel` | 显示计数的 UI 元素，挂在 `NPower` 下 |
| 计数 | `int`，来源于 `History.CardPlaysStarted` 的 `Count(...)` | 显示文本 |

不使用反射读取 `JugglingPower` 的 private 内部计数器（`Data.attacksPlayedThisTurn`），避免版本脆弱性（ADR-001 被否方案表）。

## 6. 界面与交互

- 位置：buff 图标右上角（`(-56, 0)`，与原层数标签同宽 100、右对齐）。
- 样式：完全复制游戏原层数标签，仅改位置，不改字号/颜色/描边。
- 显示规则：始终可见，含 `0`；不封顶；无动画与输入交互。
- 与原层数标签不重叠：原标签 y 为 `21..44`，角标 y 为 `0..23`。

## 7. 异常处理与健壮性

| 场景 | 处理 |
|---|---|
| 补丁应用失败（游戏更新导致方法缺失） | `ModEntry` 捕获并 `Log.Error`，mod 加载不崩溃，仅功能缺失 |
| 单个节点刷新异常 | `RefreshAll` 内逐节点 `try/catch`，不影响其他角标 |
| 节点已销毁但仍在注册表 | `RefreshAll` 中 `GodotObject.IsInstanceValid` 检查并清理 |
| 非战斗状态访问 `CombatManager.Instance` | 统计函数空判断，返回 0 |
| 非杂耍的 buff 图标 | `Sync` 首行类型判定后直接返回，不建节点 |
| 角标重复创建 | `EnsureLabel` 以 `HasNode(LabelName)` 幂等判断 |

## 8. 兼容性设计

1. **成员链兼容**：统计谓词只用 v0.107 与 v0.111 共有的成员（`CardPlay.Card` → `CardModel.Owner` → `Player.Creature`），不做条件编译、不打双包。
2. **编译目标**：以当前游戏 `data_sts2_windows_x86_64/sts2.dll` 编译；产物只引用双方共有成员，因此旧版产物可在新版运行（不对称：新版产物引用 `CardPlay.Player`，旧版无此成员）。
3. **程序集绑定**：`sts2.dll` 的 `AssemblyVersion` 固定 `0.1.0.0`，跨版本标识一致，绑定无障碍。
4. **机制差异隔离**：v0.107 的 `JugglingPower` 用 `AfterCardPlayed` 计数、v0.111 用 `BeforeCardPlayed`；本 mod 只读 History，不受差异影响。
5. **私有方法定位**：`NPower.RefreshAmount` 为 private，Harmony 以字符串名打补丁（BaseLib / RitsuLib 同样做法）。
6. **与同类 mod 共存**：BaseLib（`IHasSecondAmount`）、RitsuLib（`IPowerExtraIconAmountLabelsProvider`）各自按类型分支工作；本 mod 只匹配 `JugglingPower`，互不干扰。
7. **已知边界**：与盗版、修改版、移动版、老旧版本、冷门/次级 mod 的兼容性不作保证（`description/` 声明）。

## 9. 构建与打包

- 构建脚本：`9.SRC/JugglingCounterMod/build.ps1`，流程为
  1. 若 `%TEMP%\godot-cache` 存在且工程内无 `.godot`，先移回复用；
  2. `dotnet build`，通过命令行 global property 把 `bin`/`obj` 重定向到 `%TEMP%\build`（MSBuild 属性值中的 `%` 需转义为 `%25`）；
  3. Godot `--headless --import`，再 `--export-pack "Windows Desktop"` 生成 `JugglingCounterMod.pck`（`export_presets.cfg` 的 `export_files` 仅含 `res://JugglingCounterMod/mod_image.png`）；
  4. 把工程内 `.godot` 移回 `%TEMP%\godot-cache`；
  5. 拷贝 `dll` / `pdb` / `json` / `pck` 到 `C:\Game\Steam\steamapps\common\Slay the Spire 2\mods\JugglingCounterMod\`。
- 输出重定向的原因：`Godot.NET.Sdk` 默认写 `.godot/mono/temp` 且 `Sdk.targets` 无条件覆盖输出属性，只能在命令行以 global property 传入（ADR-002）。
- 仓库整理（2026-11-01）后原项目根 `%TEMP%` 内容已归档到 `TMP/02-缓存与临时/`；`build.ps1` 未改动，下次构建会在项目根重新生成 `%TEMP%`。

## 10. 测试方案与结果

- **游戏内回归清单（12 项，`2.PLANS §6`）**：初始 0、第 1/2/3 张递增且第 3 张触发复制、不封顶、先出攻击牌再出杂耍回溯正确、回合结束归零、敌人回合显示 0、升级（Innate）开局正常、层数叠加不影响计数、buff 移除无残留、与 BaseLib / RitsuLib 同装无冲突、长时间战斗无注册表泄漏。
- **bug 场景验证**：场景 A（先 1 张攻击牌再杂耍）显示 1→2→3（触发复制）→4；场景 B（先 2 张）显示 2→3（触发复制）。
- **版本验证**：v0.107（default）全部清单通过；v0.111.0（public beta）同样通过（用户实测，`3.DOCS/004-R §7`）。
- **自动化测试**：未记录（本仓库无单元测试/集成测试工程）。

## 11. 性能设计

- 计数为 O(n) 线性过滤 History 本回合条目，触发点仅"攻击牌打出"与"buff 图标刷新"，对战斗帧无可见影响（未做基准测试，未记录量化数据）。
- 角标节点只在对应 buff 图标存在期间存活，`_ExitTree` 注销，注册表不随战斗次数增长。
- `MegaLabel.SetTextAutoSize` 每次刷新重算文本尺寸，属游戏原有 API 行为。

## 12. 可拓展性

- 新增"其它 buff 的角标"：复用 `JugglingCounterRegistry` 的建节点/注册/注销机制，把类型判定与统计函数参数化即可（当前实现硬编码 `JugglingPower`）。
- 若未来需要新增自定义内容（卡牌/遗物等）：重新评估引入 BaseLib；若需要设置页 / 持久化 / 补丁诊断框架：重新评估引入 RitsuLib（ADR-001 "未来触发条件"）。
- 若游戏引入新的 `CardPlay` 成员或改变 `RefreshAmount` 签名：按 `2.PLANS §8` 回归清单逐项核对。
