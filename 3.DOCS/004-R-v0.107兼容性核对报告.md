## 3. 需要做的修改（计划，待用户批准后执行）

### 3.1 统计谓词（唯一代码修改）

`9.SRC/JugglingCounterMod/JugglingCounter.cs` 的 `CountAttacksPlayedThisTurn`：

```csharp
// 现（111 写法，107 编译不过）：
e.CardPlay.Player == power.Owner.Player
// 改为（107/111 双版本通用写法）：
e.CardPlay.Card.Owner.Creature == power.Owner
```

- 可编译性：`CardPlay.Card`(CardModel) → `CardModel.Owner`(Player) → `Player.Creature`(Creature) 成员链在 107 与 111 均存在（111 的 JugglingPower 源码本身使用 `cardPlay.Card.Owner != base.Owner.Player`，111 侧已 grep 确认 `Player.Creature` 存在）
- 语义等价：打出者 == buff 拥有者；与 107 官方 `AfterApplied` 谓词逐字一致，与 111 官方写法等价
- 收益：**单一 DLL 同时兼容 107 与 111**，无需条件编译、无需反射、无需双包

## 4. 版本间机制差异（不影响本 mod，记录备查）

| 差异 | 107 | 111 |
|---|---|---|
| JugglingPower 计数钩子 | `AfterCardPlayed`（打出后）++ | `BeforeCardPlayed`（打出前）++ |
| AfterApplied 回溯谓词 | `e.CardPlay.Card.Owner.Creature == base.Owner` | `e.CardPlay.Player == base.Owner.Player` |

- 本 mod 显示只读 `History.CardPlaysStarted` 实时统计（与各版本官方回溯谓词同源），不依赖内部计数钩子 → 两种机制下显示均正确
- 上一轮 bug 修复把刷新点从 `JugglingPower.BeforeCardPlayed` 改为 `CombatHistory.CardPlayStarted`，恰好也是双版本通用的正确选择：**107 根本没有 `BeforeCardPlayed`**，若原补丁保留会在 107 编译失败

## 6. 补充结论：107 编译产物在 111 上可用（2026-08-22 实施后确认）

用户追问"107 编译产物在 111 上能生效吗"，核查结论：**能**。

- **成员层面**：.NET 成员引用按名字解析。107 写法（`CardPlay.Card` → `CardModel.Owner` → `Player.Creature` 链）引用的成员在 111 全部存在（111 的 `JugglingPower` 源码自身使用 `cardPlay.Card.Owner != base.Owner.Player`；`Player.Creature` 已在 111 解包 grep 确认）→ memberref 必然可解析。不对称根因：111 产物引用了 107 没有的 `CardPlay.Player`（新版成员），旧版产物只引用双方共有成员。
- **程序集绑定层面**：sts2.dll 的 `AssemblyVersion = 0.1.0.0`（固定值，107 实测；不随游戏版本号变化）→ 跨版本程序集标识一致，绑定无障碍；0Harmony.dll 当前（107）为 2.4.2.0。
- **社区实证**：用户既有 mod（110 时期构建）在 111 上无需改码运行（v110→v111 compat 记录）；RitsuLib/BaseLib 亦以单 DLL 覆盖多版本。
- **注意点**：程序集绑定依赖 sts2.dll AssemblyVersion 与 0Harmony 版本在 111 侧一致（当前仅 107 侧实测）；发布/切换版本时仍建议实测一次。

## 7. 验证结论（2026-08-22）

- **107（default）实测通过**：计数即时递增、第 3 张触发复制、回合归零、buff 移除无残留等 §6/§12 清单项全部正常。
- **111（public beta）实测通过**：切换回 111 后同样正常，双版本兼容成立（单一 DLL 通用）。
- 结论：`min_game_version=0.107.0` 的双版本策略（ADR-003）验证有效；后续版本更新按 §8 回归清单执行即可。
