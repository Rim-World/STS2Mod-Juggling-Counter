## 3. 谓词等价性

### 3.1 三版本对照

| 版本 | 官方回溯谓词 | mod 谓词 | 结论 |
|---|---|---|---|
| 113 | `e.CardPlay.Player == base.Owner.Player`（`JugglingPower.cs:34`） | `e.Actor == power.Owner`（`JugglingCounter.cs:37`） | 等价 |
| 111 | `e.CardPlay.Player == base.Owner.Player` | 同上 | 等价 |
| 107 | `e.CardPlay.Card.Owner.Creature == base.Owner`（`JugglingPower.cs:32`） | 同上 | 等价 |

### 3.2 记录时刻的不变量

1. `CardPlay.Player = Owner`。`CardPlay` 只有一个构造点（`CardModel.cs:2083-2093`），`Player` 直接取 `Owner`。
2. `Hook.BeforeCardPlayed` 在构造后、写历史前执行（`CardModel.cs:2094`）。主审检查了全部 `BeforeCardPlayed` 实现：没有实现修改当前卡牌的 `Owner`；`ImitationLearningPower` 只创建复制品，不改变当前卡牌。
3. `CombatHistory.CardPlayStarted` 随后写入历史（`CardModel.cs:2095-2098`）。`CardPlayStartedEntry` 在基类构造时把 `cardPlay.Card.Owner.Creature` 快照进 `Actor`（`CardPlayStartedEntry.cs:34`）。
4. 全仓唯一卡牌易主入口 `CardModel.GiveToAnotherPlayer` 只被 `OnPlayWrapper` 在全部 play 结束后调用（`CardModel.cs:2161-2166`）。
5. The Ball 的 `GetResultLocationForCardPlay` 只修改 `resultLocation.player`，不直接修改 `Card.Owner`；真正的易主发生在第 4 步之后。

因此，在历史写入时刻，`Actor == CardPlay.Player`。换手后 `Actor` 保持原打出者，原玩家不少 1，接收方不多 1，与官方内部计数一致。

### 3.3 官方计数时序

- 113 的 `JugglingPower.BeforeCardPlayed` 自增（`JugglingPower.cs:38-50`），之后才写历史。mod 的刷新在 `CardPlayStarted` Postfix，晚于自增与写历史，所以第 3 张攻击牌开始时角标已是 3。
- 107 的官方计数在 `AfterCardPlayed` 自增。mod 仍在 `CardPlayStarted` 刷新，卡牌结算过程中会比官方内部计数提前一张。此差异从 1.0.0 起存在，不是 1.0.1 引入；113 上不再有该差异。

## 5. 补丁与生命周期

- 4 个补丁目标在 113 均存在，参数名可绑定：
  - `NPower.RefreshAmount`：private，零参数。
  - `NPower._ExitTree`：public override，零参数。
  - `CombatHistory.CardPlayStarted(ICombatState, CardPlay)`：Postfix 参数名 `cardPlay`。
  - `JugglingPower.AfterSideTurnEnd(PlayerChoiceContext, CombatSide, IEnumerable<Creature>)`：Postfix 参数名 `participants`。
- 刷新覆盖：buff 图标创建 / 层数变化、攻击牌写历史、己方回合结束、节点退出。
- `NPowerContainer` 按 power 创建与释放节点，不复用同一节点给不同 power；不存在旧角标残留在新 power 上的路径。
- `AfterSideTurnEnd` 清零发生在 `SwitchSides` 修改 `CurrentSide` / `RoundNumber` / `TurnNumber` 之前，补丁置 0 与官方清零同点。
- 历史只在战斗结束或取消时清空，不写存档；角标不跨战斗残留。
- `RefreshAll` 在 Harmony 主线程执行，锁只保护注册表遍历，无 Godot 跨线程调用。

### 6.1 F1 的边界说明

`HappenedThisTurn` 要求 `RoundNumber`、`CurrentSide` 和所有玩家 `TurnNumber` 与记录时一致（`CombatHistoryEntry.cs:62-75`）。官方 `BeforeCardPlayed` 自增不检查 `CurrentSide`。

在敌方侧自动打出攻击牌时，记录当下 `CurrentSide` 仍等于当前侧，角标会先计入；侧切换后该条历史的 `CurrentSide` 不再等于当前侧，角标会排除它。玩家方的 Juggling 不会在敌方侧结束时清零（`participants` 是敌方），所以官方内部计数保留，mod 显示可能少 1。该路径未在游戏内复现，列为 P3。

## 7. 1px 观感

`005-R §3` 已用同字体、同字号、同描边、1.333 倍缩放渲染核对：

- 两个标签的矩形同为 `-56..44`，右对齐，右缘同为 `x = 44`。
- 同一数字上下两行逐像素重合。
- 不同数字的右侧字形留白相差约 0.468px，1.333 倍缩放后约 0.6px；落在不同子像素相位时表现为 0–1px。
- 官方层数标签换数字时也有同样摆动。

1.0.1 未修改布局常量、字体、描边、阴影或 pck 资源。因此本次审查不改 1px。若用户仍看到固定方向的偏移，需要游戏内截图测量，不能只凭肉眼判定。

## 9. 结案建议

1. 1.0.1 保持现状。按静态审查，v0.113.0 兼容性只需要 `Actor` 谓词这一处改动。
2. F1–F4 不并入 1.0.1。它们不是 113 适配问题，且修复会引入自维护状态或扩大刷新范围，风险高于收益。
3. 若目标是「任何边缘场景都与官方内部计数完全相等」，另开计划评估自维护计数器或更广的刷新点；不要在本补丁内扩展。
4. F5 可另开清理提交删除孤立 `.uid`；F6 不改坐标，需要时先截图测量。
5. README / 注释中的「显示值与游戏实际状态一致」应按正常回合理解；若要严格表述，可在后续文档修订中补充 F1 / F2 边界。本次审查不改 README。
